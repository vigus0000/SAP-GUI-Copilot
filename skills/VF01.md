# SOP: VF01

## 目的

依出貨交貨單或銷售訂單建立客戶請款發票（Billing Document），完成開票流程並自動產生財務憑證（FI Document）。

## 前提條件

- 使用者具備 VF01 執行授權
- 參考的出貨交貨單已完成出貨過帳（Goods Issue，GI 狀態為完成）
- 客戶主檔中已設定請款資料（付款條件、請款科目等）
- 若依訂單開票（Order-Related Billing），訂單需已確認且未設開票凍結

## 操作步驟

1. 進入 VF01：在指令列 `wnd[0]/tbar[0]/okcd` 輸入 `VF01`，按 Enter。

2. 在初始畫面設定請款基本條件（均為選填，可留空由系統自動帶入）：

   | 欄位 | 說明 | 範例 |
   |---|---|---|
   | 請款日期（Billing Date） | 發票日期，留空則以今日為請款日（選填） | `2026/07/31` |
   | 請款類型（Billing Type） | 發票類型，通常由交貨單自動帶入（選填） | `F2` |

   對應 Element ID：
   - 請款日期（FKDAT）：`wnd[0]/usr/ctxtVFKD-FKDAT`
   - 請款類型（FKART）：`wnd[0]/usr/ctxtVBDKR-FKART`

3. 在文件清單區輸入要開票的交貨單號（可一次輸入多筆，系統將嘗試合併開票）：  
   文件清單 Grid Element ID：`wnd[0]/usr/cntlBILL_SPLIT_VIEW/shellcont/shell`

   在 Grid 空白列逐行輸入：

   | 欄位 | 說明 | 範例 |
   |---|---|---|
   | 交貨單號（Delivery） | 已完成出貨過帳的交貨單號 | `0080012345` |
   | 請款日期（Billing Date） | 可逐筆指定，覆蓋抬頭設定（選填） | `2026/07/31` |

4. 點選 `wnd[0]/tbar[1]/btn[8]`（或按 F8）預覽請款文件：  
   系統顯示合併後的請款明細，包含客戶、物料、數量、單價與合計金額。  
   - 若有多筆交貨單符合合併條件（相同客戶、幣別、付款條件等），系統會自動合併成一張發票
   - 若有分割（Split），可在此確認原因（通常是客戶、幣別或付款條件不同）

5. 儲存並建立請款文件：點選 `wnd[0]/tbar[0]/btn[11]`（或按 Ctrl+S）。  
   儲存成功後，畫面底部狀態列顯示「已建立請款單 9xxxxxxxxx」，記錄此 10 碼請款文件號。  
   同時，系統自動在 FI 模組產生對應的應收帳款憑證。

## 常見問題

| 錯誤訊息 / 現象 | 可能原因 | 處理方式 |
|---|---|---|
| 「交貨未完成出貨過帳」 | 交貨單 GI 尚未執行 | 至 VL02N 執行出貨過帳（Post Goods Issue）後再重試 |
| 「揀料未完成」 | 交貨單揀料數量未達交貨數量 | 至 VL02N 完成揀料確認，再執行 GI |
| 重複開票提示 | 該交貨單已存在發票 | 確認是否真的需要重複開票；若是退貨/貸項需求，應使用 VF01 搭配貸項請款類型（G2）或透過退貨流程處理 |
| 發票金額為零或不正確 | 銷售訂單定價條件設定有誤 | 回到 VA02 檢查定價條件（Pricing Conditions），必要時重新定價後再開票 |
| FI 憑證未產生 | 客戶對帳科目未設定，或 FI 期間未開啟 | 聯絡 FI 顧問確認客戶主檔公司代碼資料及會計期間設定 |
